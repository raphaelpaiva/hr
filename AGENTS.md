# AGENTS.md

Headless Recorder ("hr") — a FastAPI web app for a Raspberry Pi 3 that records audio from ALSA/USB interfaces via `arecord` + `ffmpeg`, controlled from a phone/tablet. Frontend is plain HTML + Tailwind (vendored Play build) in `static/`; no JS framework, no build step. Dark "design system" shared across all pages.

**Must run offline** — the Pi acts as its own WiFi hotspot with no internet access. Any dependency on external web resources (CDNs, remote fonts, API calls) is prohibited; all assets must ship in `static/`.

**Never run git write operations** (commit, add, branch, push, tag, etc.) unless the user explicitly asks for them.

## Commands
- Local dev: `./dev.sh` — creates `venv/` with virtualenv, then `fastapi dev src/main.py --host 0.0.0.0`
- Prod (on the Pi): `./prd.sh` — `fastapi run src/main.py --port 8000 --host 0.0.0.0`; run via systemd unit `linux/systemd/hr.service`
- Package: `./build.sh` — PyInstaller `--onefile` → `dist/hr`, then copies `static/` into `dist/`
- Deploy: `./sync.sh` — rsync to `192.168.9.29:~/hr_work/` (excludes venv, git, sessions)
- Install on Pi: `linux/install.sh` — sudoers shutdown permission + systemd unit
- Tests: `venv/bin/python -m pytest` — runs the suite in `tests/` (unit + API via `TestClient` + offline frontend checks) and prints a coverage report. Dev deps in `requirements-dev.txt` (`pytest`, `pytest-cov`, `commitizen`).
- Release (commitizen): `./bump.sh` — `cz bump --changelog` (bumps version in `pyproject.toml` + `src/app/version.py`, writes `CHANGELOG.md`, creates the release commit + `vX.Y.Z` tag), then regenerates `src/app/git_info.py` (branch/commit/tag), commits it and pushes `origin HEAD --follow-tags`. `./bump.sh --dry-run` updates the files but skips git add/commit/push. Needs a clean tree and eligible commits (`feat`/`fix`/BREAKING) since the last tag.
- `commitizen==4.10.0` is the last 4.x supporting Python 3.9; note `--files-only` (not `--version-files-only`) is the dry-run file bump flag in this version.
## Architecture
- API in `src/main.py` (FastAPI, router prefix `/api/v1`); domain logic in `src/app/`. Layering: **handlers** (thin, `main.py`) → **services** (`src/app/services/`) → **repositories** (`src/app/repositories/`) → disk. Handlers validate payload shape with Pydantic models in `src/app/schemas.py`, get services via `Depends` from `app.state` (built by `build_services()` in the lifespan), and never touch persistence directly. Services own the in-memory caches (`SessionService._sessions`, `LyricService._lyrics`, `AliasService._aliases`), apply business rules, orchestrate the `SoundSystem` and persist through repositories. Domain errors live in `src/app/exceptions.py` (`NotFound` → 404, `ValidationError` → 400) and are mapped by app-level exception handlers with the exact message strings.
- `src/app/sound_system/`: `SoundSystem` base → `AlsaSoundSystem` (spawns `arecord -L` / `ffmpeg`) and `DummyAlsaSoundSystem` (fake device list + fake record/stop so the whole flow works on macOS). `AlsaSoundSystem` keeps an **internal device list** (`self._devices`, refreshed on every `list_devices()` call) used by its helpers; `SoundDevice` is OO: `needs_full_duplex_keepalive()` (description contains `HX Stomp`, case-insensitive) and `plughw_name()` (`hw:` → `plughw:` prefix swap). Recording is **1 mono file per physical channel** of each selected ALSA device: `device_channels(name)` probes the count via `arecord -D hw:<dev> --dump-hw-params` (derives `hw:` from `plughw:`, `timeout=5`, sanity guard `MAX_CHANNELS=32`, per-process cache, fallback 2), and `start_recording(list)` runs **one ffmpeg per device group** (`-f alsa -channels N` + one `-map_channel 0.0.i -ac 1 <out_i>.wav` per channel; `-ac 1` for mono). `stop_recording` is idempotent per group key `session_id/take_id/device_name`. `Recording.channel` (`Optional[int]`, default `None`) records which physical input each wav came from (legacy `session.json` on disk defaults to `None`).
- **HX Stomp full-duplex keepalive**: the Line6 HX Stomp (USB Audio Class 2.0, asynchronous with implicit feedback) needs playback + capture running to manage its internal clock. Before starting the ffmpeg for a device group, `start_recording` checks `SoundDevice.needs_full_duplex_keepalive()` via `_find_device()` on the internal list (refreshes via `list_devices()` if empty) and spawns `aplay -D <plughw name> -f S32_LE /dev/zero` (`APLAY_SAMPLE_FORMAT`, kept at `S32_LE` to avoid artifacts) into `keepalive_processes[key]`. If aplay exits immediately, the group's recordings are marked `ERROR` and the take aborts (ffmpeg is never spawned). `stop_recording` terminates the keepalive (SIGTERM, 2s wait, `kill()` fallback) only **after** the ffmpeg process exits, and the ffmpeg-failure branch also stops it so nothing is left orphaned. `DummyAlsaSoundSystem` never spawns aplay (its `start_recording` is fully overridden); its fake `arecord -L` output includes an `hw:CARD=XL,DEV=0` / `plughw:CARD=XL,DEV=0` device with description `Line6 HX Stomp, USB Audio` so the detection logic is testable on macOS.
- Sessions persist to a **single root** `sessions/<id>/` via `src/app/repositories/session_repo.py` (`SessionRepository`, root injected in the constructor: `get_all`/`save`/`delete`/`find_wav`), written atomically through `src/app/repositories/base.py` (`atomic_write` = tmp file + `flush` + `os.fsync` + `os.replace`; `load_json` logs and keeps corrupt files on disk). Each session dir holds `session.json` — the **single source of truth** for state, including every recording's `state`/`error_code`/`last_modification`; there are no per-recording json files. `Recording` requires `session_id` + `take_id` (raises `ValueError` otherwise) and computes `base_dir`/`output_path` under a `base_dir` passed by the caller (`SessionService` passes `repo.root` on create; `SessionRepository` passes it on load via `Session.from_dict(data, base_dir=...)` → `Take.from_dict` → `Recording(from_dict=..., base_dir=...)`; default is `config.BASE_PATH`). `Recording.mark_started/stopped/error` mutate memory only — persistence happens when the service saves the session. Deleting a session (`repo.delete`) removes its wavs too.
- Lyrics (vocalist reading screen) live in a separate root `lyrics/<id>.json` (flat files, atomic write) via `src/app/repositories/lyric_repo.py` (`LyricRepository`, root injected: `get_all`/`save`/`delete`), served by `src/app/services/lyric_service.py` (`LyricService`). `Lyric` (`src/app/lyrics/lyric.py`) has `id`/`name`/`text`/`created_at`/`updated_at`. API: `GET/POST /api/v1/lyrics` (list sorted by name, create), `GET/POST /api/v1/lyrics/{id}` (read, update — 400 `"Name is required"` if blank, 404 if missing), `DELETE /api/v1/lyrics/{id}`. Pages: `GET /lyrics` (list + create/edit form) and `GET /lyrics/read?id=` (reader).
- Frontend design system (no build step):
  - `static/js/tailwind.config.js` — theme tokens (`ink`/`surface`/`card`/`edge`/`hover`) + Inter font family. Must be loaded **before** `static/js/tailwind.min.js` (vendored Play build).
  - `static/css/app.css` — `@font-face` for the bundled Inter variable font, base `body`, `.card-bg`/`.input-bg`/`.border-custom`, `.glow-effect` + `@keyframes pulse-red`
  - `static/js/app.js` — renders the shared top nav into `<header id="app-header" data-page="...">` (health pills, Sessões/Letras links, shutdown button) and exposes `api()`, `formatTimestamp()`, `formatTakeTimestamp()`, `updateHealth()`
  - `static/js/keep-awake.js` — keeps the phone screen on while the reader is open. The Pi serves plain HTTP (insecure context), so the native `Wake Lock API` is unavailable; this file tries `wakeLock` first (progressive enhancement for a future HTTPS) and falls back to a silent-media loop (Android: Web Audio buffer; iOS: tiny base64 silent `<video loop muted playsinline>`). Requires a user gesture — the reader primes it on first touch/pointerdown.
  - Pages: `static/index.html` (new-session screen + recent sessions, `/`), `static/session.html` (sessions list, `/sessions`), `static/session_detail.html` (session + takes, `/sessions?id=`), `static/lyrics.html` (lyric create/edit + list, `/lyrics`), `static/lyrics_reader.html` (focused reader with font-size controls persisted in `localStorage`, `/lyrics/read?id=`; no `#app-header`)
  - Each page uses the shared assets in `<head>` + an inline page-specific `<script>`; no templating, header markup is duplicated from `app.js`
- Session takes: `POST /api/v1/session/{id}/take/start` accepts `{"devices": [...]}` (defaults to the session's saved devices) and spawns **one `Recording` per physical channel** of each device (`channel=0..n-1`, where `n = device_channels(device)`); `take/stop` stops the active take (latest take with recordings in `RECORDING` state); `POST .../take/{take_id}/rename` accepts `{name}` (400 `"Name is required"` if blank) and renames a take; `GET .../take/{take_id}/zip` streams a ZIP of the take's wavs (names get a `_ch{n+1}` suffix via `make_wav_name(..., channel=rec.channel)`). `GET /api/v1/devices` exposes `channels` per device (cached). `POST /api/v1/session/start` is the main-screen "new session" flow: it creates a named session (`{name, devices}`) and starts recording in one step, returning `{session_id, take}` (400 `"No devices selected"`; a blank/omitted `name` becomes `Sessão de <dd/mm/aaaa hh:mm>`). `POST /api/v1/quick/start` is the legacy "quick record": it creates an anonymous session (`Anônima <dd/mm HH:MM>`) with a single take and returns `{session_id, take}`. `/api/v1/history` returns sessions (sorted by `created_at` desc). There is no standalone record flow — everything is a session. These rules live in `SessionService`, not in the handlers.
- One-time migration from the old `recordings/<id>/` layout: `python scripts/migrate.py` (run **once** from the repo root before first boot of the new version). It moves Phase-A session recordings into `sessions/<sid>/takes/<tid>/` and wraps any orphaned standalone recordings as anonymous `Migrada <dd/mm HH:MM>` sessions, then removes the empty `recordings/` dir. It no longer writes per-recording `<rec_id>.json` files — state lives only in `session.json`.
- Build/version info: `src/app/version.py` holds the app version (bumped by commitizen), `src/app/git_info.py` is generated by `bump.sh` (branch/commit/tag, falls back to empty strings in `build_info.py` if missing); `GET /api/v1/meta` exposes `{version, branch, commit, tag}`. The header shows the version and the footer shows the git info.

## Gotchas
- `src/main.py:28` hardcodes `AlsaSoundSystem()` (needs ALSA + `arecord`/`ffmpeg`). On macOS, switch the active line to `DummyAlsaSoundSystem()` (line 29) for local testing. It is consumed by `build_services()` (lifespan) and by `/devices`; the services hold their own `DummyAlsaSoundSystem` in tests.
- `static/` is served relative to the **cwd** (`StaticFiles(directory="static")`); all storage lives under `./sessions/` (single root). Run the server from the repo root (and the PyInstaller binary from `dist/`).
- The local `venv/` is broken — its python symlink points to an uninstalled Homebrew python@3.13. `./dev.sh` recreates it; system python is 3.14.
- `linux/install.sh` has inconsistent relative paths: the sudoers step needs cwd = repo root, the `systemd/hr.service` step needs cwd = `linux/`. Also `hr.service` expects the app at `/home/<user>/hr`, while `sync.sh` copies to `~/hr_work/` — reconcile on the Pi.
- Python sources use 2-space indentation (not PEP8). Match it.
- **Python 3.9 is the minimum supported version** (Pi + `Dockerfile` `python:3.9-slim`). Do NOT use PEP 604 unions (`X | None`) in annotations — use `typing.Optional`/`Union`. `requirements.txt`/`requirements-dev.txt` are pinned at the 3.9 ceiling (`fastapi==0.128.8`, `uvicorn==0.39.0`, `starlette==0.49.3`, `pytest==8.4.2`); bumping them requires re-verifying on 3.9 (the local dev venv is 3.14, which won't catch a 3.10-only dep or `|` annotation).
- `take/start` returns 400 if no devices are selected and the session has no saved devices; `take/stop` returns 400 if no take is currently recording; `session/start` returns 400 if no devices are given (a blank name auto-becomes `Sessão de <dd/mm/aaaa hh:mm>`); `quick/start` returns 400 if no devices are given. Take names are click-to-rename on `static/session_detail.html` (table + mobile cards) via `POST .../take/{id}/rename`, but clicks are disabled while a take is recording (`recordings[].state === 'recording'`). `Session.to_dict()` must call `take.to_dict()` (parenthesized) — a bound-method reference there silently breaks the session detail API.
- `DummyAlsaSoundSystem` also fakes record/stop (marks states, stores recordings, no ffmpeg), so sessions and take start/stop are all testable on macOS.
- The Pi's `ffmpeg 4.3.9` (`-h demuxer=alsa`) exposes only `sample_rate`/`channels` — no `buffer_size`/`period_size` — so the ~0.75s ALSA ring-buffer tail loss at stop is accepted (unfixed). `-map_channel` is the index-based split (works for any N, no named channel layout); `channelsplit` needs a named layout and fails for odd counts like 14. The `plughw:` probe with `arecord --dump-hw-params` hangs (plug inflates `CHANNELS: [1 10000]`) — always probe on `hw:`.
- Tests never touch real hardware or the live `sessions/` dir: `tests/conftest.py` swaps in `DummyAlsaSoundSystem`, patches `main.SOUND_SYSTEM` (used by `/devices`) and `main.build_services` so the app's services run on repositories rooted at a temp dir, and patches `main.run` so `POST /shutdown`'s background `sudo shutdown` never fires. Unit tests construct `Recording(...)` with `base_dir=tmp_recordings` — omitting it makes paths fall back to the real `./sessions/`. Note this Starlette's `TestClient.delete()` doesn't accept `json=` — use `client.request('DELETE', url, json=...)`.
